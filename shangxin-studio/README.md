# 上新 Studio · AI 商品文案

本次将原型中的规则文案替换为服务端 OpenAI API 调用。输入商品名称、卖点及选填属性，返回标题、简介和三条卖点。图片仍由原图与 Canvas 排版，不属于 AI 生图。

## 本地运行

需要 Node.js 22 或更高版本，无需安装依赖。在本项目目录创建 `.env.local`，填写自己的服务端配置：

```dotenv
OPENAI_API_KEY=填写自己的密钥
OPENAI_MODEL=gpt-4.1
```

`.env.local` 已被 Git 忽略。不要提交、截图或把密钥写进 public 目录。

```sh
npm run dev
```

打开终端显示端口对应的本地页面（默认 http://localhost:5173）。本地调试只用于本人可信环境，不作为公网服务器。

## 网站部署

现有上新 Studio 网站保持仅本人可访问。Worker 通过环境变量读取密钥；浏览器只向同源 `/api/generate` 发送商品文字资料。图片与参考链接不发送至 OpenAI。

在托管环境配置 `OPENAI_API_KEY`（秘密变量）及可选 `OPENAI_MODEL`，再部署保存版本使配置生效。本站当前默认 `gpt-4.1`。GitHub 用于代码保存；GitHub Pages 只支持静态网页，不能运行此服务端接口。

```sh
npm test
npm run build
```

构建输出为 `dist/server/index.js`，包含静态资源和 Worker 接口。`.openai/hosting.json` 保留原网站身份；dist 为构建产物，不提交密钥或本机数据。运行日志只记录时间、模型、状态、请求编号、耗时和 Token 数，不记录密钥与商品正文。

## 完成作业的最后验收

1. 配置有效密钥和可用额度后，打开工作台，添加一件商品，只勾选这一件。
2. 点击“AI 生成文案”，确认出现标题、简介、三条卖点。核对没有编造价格、销量或功效。
3. 展开草稿的“查看本次 AI 调用记录”，保存成功页面截图。
4. 用请求编号核对服务端 `ai_generation` 日志；到 OpenAI Usage 确认该时段用量。
5. 换另一件商品、留空一个选填字段重试。错误路径已用隔离测试覆盖，无需故意破坏生产密钥。
6. 使用说明中的“下载本机调用记录”可导出最近 50 次记录。浏览器记录可被本地修改，应结合服务端日志或平台用量核验。

作业说明句（真实验证通过后使用）：**AI 根据用户填写的商品资料生成标题、简介和三条卖点，用户核对后可继续编辑并导出文案。**

## 行为与限制

请求逐件发送，45 秒服务端超时，55 秒浏览器超时；生成中防重复点击，可在当前商品结束后停止。失败时保留已成功草稿，只重试未完成商品，不自动重试付费请求，不降级为模拟文案。旧版草稿明确标注“旧版模拟草稿”。

JSON Schema 约束输出，服务端再次校验；输入限制长度、拒绝跨站请求。部署依赖现有仅本人可访问的 Sites 访问控制，不应直接改为公开付费 API；开放多人使用前需要独立鉴权、配额和速率限制。

商品、草稿、模板及调用记录保存在当前浏览器；换设备不同步，草稿最多 90 份。支持 XLSX/CSV 导入、PNG/CSV 导出及模板复用。AI 可能出现事实错误，上架前必须人工复核。模板仅参考表达结构，不继承旧商品事实。
